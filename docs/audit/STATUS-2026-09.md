## Remaining defects

**G2 — PARTIAL.** The bare-season dead end is fixed, but only for a season with *neither*
tiers nor a config row. `bot/workflow.py::seed_preset_into_season` refuses outright once
tiers exist ("already has tiers … Edit settings from the config panel instead"), and
`bot/workflow.py::add_tier` happily inserts tiers with no config row present. So: create a
season without a preset → add a tier via Setup → Tiers (or `/market-admin tier add`) →
`seed-preset` now refuses and the config panel it redirects to raises "no league config
row". Second residual: `bot/workflow.py::run_valuation` (the `cfg is None` branch, ~line 267)
still raises *"No league config for that scope. Seed one with the F1 preset first."* —
advice that cannot be followed for a season that already exists. It is reachable from the
typed `/market-admin valuation run` (`admin_market.py`), Race Night (`panel.py`) and the
offseason wizard (`offseason_screen.py`). Start at
`workflow.py::seed_preset_into_season` (relax the tiers guard to config-row-only, or add a
config-only seed) and `workflow.py::run_valuation`.

## Method and its limits

Findings were re-traced from source with callers verified by grep; no tests
were run for this pass, so "FIXED" means the wrong behaviour is no longer
reachable in code, not that a test pins it. Two cases where that gap matters:

- **G5** (no global exception handling) is FIXED via
  `bot/main.py::RosterBot._on_app_command_error`, `base.OwnedView.on_error`
  and `base.PanelModal.on_error`, but **no test exercises any of them**.
- **G15** is FIXED because the three race-night views now extend
  `base.AdminOwnedView`, whose `interaction_check` re-runs `is_admin` per
  click — but `tests/test_panel_screens.py::test_every_screen_is_admin_gated`
  walks `bot/ui/*` and does not cover those three views in `bot/cogs/panel.py`.

**G25** was fixed by validation (`workflow.py::find_rank_conflict`, enforced in
`add_tier` and `edit_tier`) rather than by the `UNIQUE (season_id, rank_order)`
constraint the finding asked for. No such constraint exists in `migrations/`,
so a future writer that bypasses those two helpers would reintroduce duplicate
ranks. Today no such writer exists.
